what margay sees

Three permission bugs that quietly ruin your week.

001 / exec bits

Scripts that forgot to be executable.

You wrote deploy.sh on Windows. You committed it. CI runs it. CI dies with permission denied. margay flags every shell script missing the user-execute bit so you can patch them before the pager fires. 

$ margay
Shell scripts missing +x
  +x scripts/deploy.sh    0644 → 0744
  +x scripts/migrate.sh   0644 → 0744

$ margay
Sensitive files too open
  !! .env              0644 → 0600
  !! secrets/api.key   0664 → 0600

002 / loose secrets

Secrets sitting at 0644.

Every .env, *.key, *.pem, and id_rsa in your tree should be 0600 or stricter. margay finds the ones that aren't and tells you exactly which line of chmod to run — or just runs it for you with --fix.

003 / accidental exec

Source files marked executable.

A stray chmod -R 755 turns README.md and every *.rs into "executables." Harmless, embarrassing, and a permanent eyesore in git status. margay catches them. 

$ margay --fix
margay: fixed 5 issue(s)

$ margay
✓ no permission issues found

drop into ci

One job, zero regressions.

Add margay to GitHub Actions and a permission bug never makes it back into main. Exits non-zero on findings, JSON output for tooling, no flaky network calls.

full docs on github → 
# .github/workflows/perms.yml
name: Audit Permissions
on: [push, pull_request]

jobs:
  perms:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo install --git https://github.com/iamkorun/margay
      - run: margay
